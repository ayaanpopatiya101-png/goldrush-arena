For GoldRush Arena, avoid gradients, blue side icons, pure white backgrounds, rainbow coloring, drop shadows on everything, three feature cards in a row, emojis, liquid glass, em dashes, Inter, Geist, Space Grotesque, decorative colored stripes, fake testimonials, bento grids, terminal windows, "It's not X, it's Y" copy, checkmark bullets, three pricing tiers, soft corner radii, purple and black, radial orbs, dot grids, sparkle icons, animated arrows, hover animations for everything, neon colors, and basic pastel colors.

The same avoidance list includes "no real product demos", "no skeleton loaders", "no TOS", and "no privacy policy". Preserve that wording and treat these as omissions to avoid: retain actual product demonstrations and appropriate loading states, Terms, and Privacy. This interpretation was stated when presenting the upgrade plan, not separately confirmed by the user.

**Why:** The user explicitly requested these constraints for the GoldRush Arena upgrade. They supersede older Inter and glow-heavy aesthetic preferences in project guidance.

**How to apply:** Apply when planning or changing this game's visual UI and copy. External reference apps are inspiration for usability, not permission to reproduce styles on the avoidance list.

The user subsequently asked for "more color instead of looking bland and boring." The avoidance list is not a request for a gray or nearly colorless app.

**Why:** The user found the restrained redesign too bland and asked for stronger color.

**How to apply:** Keep purposeful, richer solid color in this game while preserving the explicit bans, especially gradients, neon, rainbow schemes and basic pastels.

The user requested a blend of neo-brutalism, 3D elements, bold typography, retrofuturism, gamified icons (including the app logo), vibrant colors without the AI-gradient look, neumorphism, and textures. Try all, but omit a style if it does not fit the game.

**Why:** The user explicitly requested this visual direction for GoldRush Arena.

**How to apply:** Combine these treatments coherently while preserving readability and the earlier avoidance list. The user allows unsuitable styles to be left out.

The later full-app brief prioritizes a professional physical air-hockey presentation with engraved brass scoreboards, restrained pine/charcoal surfaces, and meaningful color. Real engine demonstrations and honest local-bot, device-local-profile, unavailable-store and pre-release labels take priority over decoration.

**Why:** The user supplied this more specific direction for the production app after the exploratory eight-style request.

**How to apply:** Use it to resolve conflicts with earlier explorations. Do not add decorative effects merely to demonstrate every style, or present coordinated parties as synchronized human PvP.

The user selected the “Tactile Arcade (unslop refined)” Home reference and asked for the actual app to look like it: green surfaces, cream/brass framing and mode panels, a stamped court emblem, coral accents and condensed headings.

**Why:** This is the user's explicit visual choice for the app, not an unapproved alternative.

**How to apply:** Preserve that composition when changing the mobile UI, but use the later explicit colour palette below instead of the green material palette. The user wants the same design across the rest of the app, not only Home. Translate its static court into the real engine and use actual profile/season data rather than copying illustrative values.

The user approved a usability review that prioritizes Play over moving practice content: practice is opt-in, playable activities precede advanced locks, and secondary systems should appear when relevant. Keep progression balance unchanged.

**Why:** The user approved the review's recommended changes after selecting the tactile design; the screenshot's content order is not a requirement to keep Home distracting.

**How to apply:** Preserve the approved materials and identity while reducing cognitive load. Cosmetic previews must not promise material or shape properties the actual game does not implement.

Use Duolingo's one-choice-at-a-time flow and visual personalization as the primary onboarding reference; see page-design-references.md.

**Why:** The user's newer page-by-page guide supersedes the earlier Atoms reference.

**How to apply:** Use the reference for the onboarding experience while retaining GoldRush's approved identity and the avoidance list above.

The user replaced the app palette with Warm Stone `#EEE9DE` for main backgrounds and light text on navy; Sandstone `#E3DFD3` for panels; Charcoal Ink `#252A2B` for headings/body/button labels; Slate `#575D5C` for supporting text; Vermilion Orange `#F36B3F` for Play and the player paddle; Arcade Gold `#EDBA3C` for branding/rewards/progression; Court Navy `#23344B` for the arena and selected dark sections.

**Why:** The user supplied these exact colours and roles as the new app design direction.

**How to apply:** This replaces earlier pine/green background preferences. Keep the other visual constraints and preserve existing saved or owned cosmetic identities. Use readable charcoal labels on orange/gold fills, rather than low-contrast gold/orange body text on stone.

The user subsequently requested a 60/30/10 colour scheme across the app. Use
approximately 60% warm stone for the main surfaces, 30% court navy for important
sections and the arena, and 10% vermilion orange for actions and selected states.
Keep gold confined to brand details, rewards and existing cosmetics rather than
large generic UI surfaces.

**Why:** The user asked for dominant, secondary and loud accent colours using the
60/30/10 rule; this allocation preserves GoldRush's identity with less competing colour.

**How to apply:** Treat the proportions as an overall visual hierarchy, not a
pixel quota for every screen. Pair navy with stone text and orange with charcoal.
Do not recolour a player's purchased or selected cosmetic to force the ratio.

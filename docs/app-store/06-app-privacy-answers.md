# App Privacy Answers

Use these answers only after confirming the production server and RevenueCat configuration match this release.

## Data collected

### Purchases — Purchase History

- Collected: Yes
- Purposes: App Functionality; Analytics
- Linked to identity: No, provided RevenueCat remains configured with its anonymous generated app user ID
- Used for tracking: No

### Identifiers — User ID

- Collected: Yes
- Description: Random installation/player identifiers used by game services for matchmaking, challenges, referrals, reward integrity, and party sessions
- Purposes: App Functionality
- Linked to identity: No
- Used for tracking: No

### User Content — Other User Content

- Collected: Yes
- Description: Player-selected display name and avatar emoji sent when online party or matchmaking features are used
- Purposes: App Functionality
- Linked to identity: No
- Used for tracking: No

### Usage Data — Product Interaction

- Collected: Yes
- Description: Challenge scores, rank, referral activity, party and matchmaking events needed to operate online game features
- Purposes: App Functionality
- Linked to identity: No
- Used for tracking: No

## Not collected

This is a draft worksheet, not a completed App Store declaration. The integrated app retains optional avatar camera/photo-library functionality and clip sharing. Verify whether images or clips leave the device and how identifiers and analytics are associated before selecting data categories. Device permission access and server-side collection are different questions. Use the current in-app privacy disclosure and verify each configured service; do not reuse a blanket “not collected” answer.

RevenueCat requires Purchase History disclosure. Re-check this worksheet if custom RevenueCat user IDs, attribution integrations, advertising SDKs, crash reporting, or new analytics are added.
